Vineflower is an open-source Java and JVM language decompiler that turns compiled `.class` files, JARs, and ZIPs back into readable source code. It is designed for developers who need accurate, clean decompilation output — whether for reverse engineering, dependency auditing, IDE integration, or building tooling on top of a programmable decompilation API. Vineflower can be invoked from the command line as a standalone tool or embedded directly in your application as a library.

## Fork Lineage

Vineflower stands on the shoulders of years of community iteration on Fernflower, the original decompiler created by Stiver and maintained by JetBrains. Each fork improved upon its predecessor before Vineflower emerged as the current state of the art.

| Project | Maintainer | Role |
|---|---|---|
| **Fernflower** | Stiver / JetBrains | Original bytecode-to-Java decompiler |
| **ForgeFlower** | MinecraftForge Team | Added fixes and improvements for Forge toolchain |
| **Fabric's Fernflower** | FabricMC Team | Parallelism and quality improvements for Fabric toolchain |
| **Quiltflower** | Quilt Project | Introduced the plugin system and extensive output improvements |
| **Vineflower** | Vineflower Dev Team | Continued development — current active project |

Special thanks to Stiver, JetBrains, the MinecraftForge Team, and the FabricMC Team for their foundational work that made Vineflower possible.

## System Requirements

Vineflower's Java version requirement depends on which release series you use:

| Vineflower Version | Minimum Java Version |
|---|---|
| 1.9.x | Java 11 |
| 1.10.x | Java 11 |
| 1.11.x | Java 17 |
| 1.12.x (current) | Java 17 |

<Note>
  The Java version requirement applies to the JVM **running** Vineflower, not to the bytecode being decompiled. Vineflower can decompile class files targeting Java 8 through Java 25 regardless of which supported JVM version you use to run it.
</Note>

## How Vineflower Works

At a high level, Vineflower's decompilation pipeline processes each method through five major stages:

1. **Bytecode reading** — parses raw bytecode into an internal instruction sequence.
2. **Control flow graph analysis** — transforms the instruction sequence into a graph of basic blocks connected by control-flow edges.
3. **Structured statement recovery** — converts the arbitrary control flow graph into structured statements (loops, conditionals, try/catch) that are valid Java.
4. **Expression parsing and simplification** — reconstructs readable expressions from JVM stack operations using SSA analysis.
5. **Java writing** — `ClassWriter` traverses the statement and expression tree to emit final source text.

This pipeline is extensible: the plugin system allows custom passes to be injected at any stage, and language plugins can replace the graph parser and statement writer entirely to support non-Java JVM languages.
